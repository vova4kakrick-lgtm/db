# Базы данных: подготовка к контрольной

Статический учебный справочник по курсу «Базы данных» (майнор ИАД, НИУ ВШЭ, 2026): теория по темам, задачи с решениями и вопросы для самопроверки. Содержание составлено по лекциям из папки `lectures/` и вариантам прошлых лет из `previous_years/`; у каждого фрагмента указан источник (файл и страница PDF).

Сайт ничего не сохраняет: нет `localStorage`, cookies, аналитики и учётных записей. Ответы открываются кнопкой «Показать ответ» (`<details>`) и снова скрываются после перезагрузки.

## Быстрый старт

Нужен Node.js 20+ (CI использует 22).

```bash
npm install          # нужна только dev-зависимость PGlite для проверки SQL
npm run build        # собрать сайт в dist/
npm run serve        # открыть http://localhost:8080/db/ — как на GitHub Pages, в подкаталоге
npm run check        # всё сразу: контент → сборка → ссылки → SQL
```

Отдельные проверки:

| Команда | Что проверяет |
| --- | --- |
| `npm run check:content` | обязательные поля, уникальные id, ссылки на теорию и источники, номера страниц, наличие фикстур |
| `npm run check:links` | все внутренние ссылки и якоря в `dist/`, отсутствие путей от корня домена, один `<h1>`, отсутствие обращений к хранилищу браузера |
| `npm run check:sql` | выполняет SQL каждого решения в PostgreSQL 18 (PGlite, WebAssembly) на тестовых данных и сверяет результат с ожидаемым; `npm run check:sql -- <id задачи>` — одна задача, `SHOW=1` — печать результатов |

Сборка не использует сторонних пакетов: генератор — несколько модулей на чистом Node.js.

## Публикация на GitHub Pages

Workflow `.github/workflows/pages.yml` на каждый push в `main` запускает `npm run check` и публикует `dist/`; в pull request выполняются только проверки.

Однократная настройка репозитория:

1. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
2. Сделать push в `main` (или запустить workflow вручную во вкладке Actions).
3. Сайт будет доступен по адресу `https://<username>.github.io/<repository>/` (для этого репозитория — `https://vova4kakrick-lgtm.github.io/db/`).

Все ссылки на сайте относительные, поэтому он работает и в подкаталоге репозитория, и в корне домена. Файл `.nojekyll` отключает обработку Jekyll.

> Учебные PDF и варианты прошлых лет на сайте **не публикуются** — указываются только их названия и страницы.

## Устройство проекта

```
content/                 учебный контент (отдельно от кода сайта)
  course.js              название курса, реестр источников (sources), порядок тем (topicOrder)
  topics/<id>/
    index.js             тема: заголовок, описание, разделы теории, термины
    tasks.js             задачи темы (в exam-practice собираются из tasks-*.js по вариантам)
    questions.js         вопросы для самопроверки
  fixtures/*.sql         схемы и тестовые данные для проверки SQL-решений
src/
  content.js             загрузка контента, обратные ссылки «раздел → задачи»
  markup.js              мини-разметка (подмножество Markdown) и подсветка SQL
  templates.js           макет страницы, ссылки, кнопка ответа, источники
  build.js               генерация страниц и поискового индекса в dist/
  assets/                styles.css, search.js (клиентский поиск), favicon.svg
scripts/                 build, serve, check-content, check-links, check-sql
dist/                    результат сборки (в .gitignore)
```

Страницы сайта: главная, карта тем (`topics/index.html`), страница каждой темы, задачи по темам (`tasks/<id>.html`), вопросы по темам (`questions/<id>.html`), поиск (`search.html`), источники (`sources.html`).

## Формат контента

### Источник (`source`)

```js
{ doc: 'norm', pages: '7' }          // doc — ключ из content/course.js → sources
[{ doc: 'l04', pages: '10–13' }, { doc: 'varA' }]
```

`pages` — номер страницы **PDF-файла** (на некоторых слайдах напечатанный номер отличается на 1).

### Тема — `content/topics/<id>/index.js`

```js
export default {
  title: 'Нормализация: ФЗ, ключи, 1НФ–НФБК, синтез 3НФ',
  short: 'Нормализация',            // короткое имя для ссылок и бейджей
  summary: 'Одно-два предложения о теме.',
  sources: ['norm'],                // ключи источников темы
  sections: [
    {
      id: 'bcnf',                   // якорь: topics/normalization.html#bcnf
      title: 'Нормальная форма Бойса–Кодда',
      source: [{ doc: 'norm', pages: '14' }],
      body: `Текст в мини-разметке…`,
    },
  ],
  terms: [{ term: 'Суперключ', def: '…', source: { doc: 'norm', pages: '7' } }],
};
```

### Задача — элемент массива в `tasks.js`

```js
{
  id: 'norm-bcnf-enrollments',      // уникален на всём сайте: tasks/normalization.html#task-<id>
  title: 'Enrollments и НФБК',
  level: 3,                         // 1 — базовая, 2 — средняя, 3 — повышенная
  group: 'Вариант А (2025)',        // необязательно: подзаголовок на странице задач
  statement: `Условие…`,
  answer: `Краткий ответ…`,
  solution: `Пояснение… {{sql}} …`, // {{sql}} — место для кода из поля sql
  theory: ['normalization#bcnf'],   // обязательно: ссылки «тема#раздел» на теорию
  source: [{ doc: 'norm', pages: '14' }],
  basis: 'derived',                 // material | derived | not-found (см. ниже)
  sql: {                            // необязательно: проверяемый SQL
    fixture: ['uni'],               // файлы content/fixtures/<имя>.sql; [] — пустая база
    code: `SELECT …`,               // или file: 'blog-schema' — взять код из фикстуры
    expect: [{ name: 'Кант' }],     // точный результат (сравниваются только указанные столбцы)
    // expectSubset: [...]          // или: эти строки должны встретиться в результате
  },
}
```

`basis` показывает происхождение ответа:
- `material` — ответ взят из материалов курса;
- `derived` — готового ответа нет, решение составлено по правилам и примерам лекций;
- `not-found` — «В материалах курса не найдено» (например, PostGIS).

### Вопрос — элемент массива в `questions.js`

```js
{ id: 'norm-q-fd', q: 'Что такое ФЗ?', a: 'Ответ…', source: { doc: 'norm', pages: '5' }, theory: ['normalization#fd'] }
```

Формулировка вопроса — один абзац.

### Мини-разметка

Абзацы через пустую строку; `### заголовок`; списки `- ` и `1. `; врезка `> текст`; таблицы `| a | b |` со строкой `| --- | --- |`; блок кода ` ```sql `; инлайн `` `код` ``, `**жирный**`, `*курсив*`; ссылки `[текст](адрес)`. Внутренние ссылки: `topic:<тема>#<раздел>`, `tasks:<тема>#<id задачи>`, `questions:<тема>#<id вопроса>` — они превращаются в относительные пути и проверяются `check:content`.

Внутри шаблонных строк JS экранируйте обратные кавычки: `` \` ``.

## Как добавить тему, задачу или вопрос

1. **Задача/вопрос:** добавьте объект в `tasks.js` / `questions.js` нужной темы, укажите `theory` и `source`. Если есть SQL — укажите фикстуру и `expect`.
2. **Новая тема:** создайте `content/topics/<id>/` с тремя файлами по образцу и добавьте `<id>` в `topicOrder` в `content/course.js`.
3. **Новый источник:** добавьте запись в `sources` в `content/course.js` (`file`, `title`, `pages`).
4. Запустите `npm run check` и исправьте сообщения об ошибках.
